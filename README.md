# 후불결제 프로토타입 (부릉 프렌즈 기사앱)

Figma [후불결제](https://www.figma.com/design/u3qTdSzPaWpS6P6AlGdR8w/) 파일의 후불현금 결제 플로우를
클릭 가능한 웹 프로토타입으로 구현한 것입니다. 360×740 (Android 360dp) 기준.

```bash
npm install
npm run dev
```

## 공유 링크 (Wi-Fi 없이 보기)

```bash
npm run build:artifact
```

`dist/artifact.html` 한 장이 나옵니다. 외부 요청이 0이라 어디서든 열립니다 — 폰·다른 사람 기기 모두.
Claude Artifact로 배포된 현재 링크:

**https://claude.ai/code/artifact/b9d6cf80-5c0f-45be-b7af-c128ea577af0** (비공개, 공유는 페이지의 공유 메뉴에서)

화면을 추가한 뒤 갱신할 때는 `npm run build:artifact`를 다시 돌리고 **같은 URL로 재배포**하면 됩니다.

단일 파일로 만들기 위해 한 것들:

| 항목 | 처리 |
| --- | --- |
| 라우팅 | 해시 라우팅(`#/delivery`) — 새로고침·딥링크 동작 → [main.tsx](src/main.tsx) |
| 지도 | 2.3MB PNG → WebP q85 **287KB** (2배 해상도 유지) |
| 폰트 | 외부 CDN 제거, 실제 쓰는 195자만 서브셋해 굵기당 21KB 내장 |
| 에셋 | 전부 data URI로 인라인 → [vite.config.ts](vite.config.ts) |
| 문서 골격 | Artifact가 씌워주므로 벗겨냄 → [scripts/make-artifact.mjs](scripts/make-artifact.mjs) |

최종 크기 **1,182KB** (gzip 약 683KB). NFC 애니메이션(137KB)과 지도(287KB)가 대부분입니다.

### 폰트 서브셋 갱신

새 문자열을 추가하면 그 글자가 폰트에 없어 시스템 폰트로 대체됩니다. 다시 만들려면:

```bash
npm run build   # 번들에 실제 들어간 문자를 뽑기 위해 먼저 빌드
```

그다음 번들에서 고유 문자를 모아 `pyftsubset`으로 세 굵기를 다시 만듭니다
(`fonttools` + `brotli` 필요, 원본은 맥의 `~/Library/Fonts/NotoSansCJKkr-{Regular,Medium,Bold}.otf`).

## 폰에서 실제 앱처럼 보기

폰에서는 프레임을 **폭 기준으로 맞추고 화면 높이는 기기 높이를 따릅니다** — 실제 앱처럼
하단 바가 화면 밑에 붙고, 여백은 화면 높이에 맞춰 늘거나 줄어듭니다.
디자인 높이(740)에서는 Figma 좌표가 픽셀 단위로 그대로 재현됩니다.

브라우저 크롬까지 없애고 보려면 **홈 화면에 추가**가 가장 가깝습니다:

1. Mac에서 `npm run dev` (같은 Wi-Fi 필요)
2. 폰 Safari에서 `http://<맥 IP>:5173` 접속
3. 공유 → 홈 화면에 추가 → 홈에서 실행

`apple-mobile-web-app-capable` 메타가 들어 있어 주소창·탭바 없이 전체화면으로 열립니다.

Claude Artifact 링크로 볼 때는 claude.ai의 헤더가 화면 위쪽을 차지해서 세로 공간이 줄어듭니다.
그래도 폭은 꽉 차고, 짧은 높이에서는 NFC 일러스트가 비율을 유지하며 작아집니다.

## 폰에서 보기 (요약)

`npm run dev`는 `vite --host`로 실행되어 같은 Wi-Fi의 다른 기기에서도 접속할 수 있습니다.
터미널에 찍히는 `Network:` 주소를 폰 브라우저에 입력하세요 (예: `http://10.5.201.154:5173`).
맥의 IP는 `ipconfig getifaddr en0`으로 확인합니다.

폭은 `transform: scale`로 맞추므로 디자인의 픽셀 위치와 비율이 그대로 유지됩니다.
480px 이하에서는 프레임 장식(라운드·그림자)을 없애고 화면 높이를 기기 높이에 맞춥니다.
→ `useDeviceScale` in [App.tsx](src/App.tsx)

`--host`는 0.0.0.0에 바인딩하므로 같은 네트워크의 누구나 접속할 수 있습니다. 사내 Wi-Fi에서 쓸 때는
필요할 때만 켜두세요.

## 플로우

```
배달지 상세 (픽업후·후불현금)
  ├─ [결제 방법 변경 >] → 결제 방법 선택 시트
  │                        ├─ 현금 → 시트 닫힘 + 현금 결제 확인 얼럿
  │                        ├─ 카드 → 카드 결제 · NFC 화면
  │                        └─ QR 간편 / 분할 → 하단 바 갱신 + 안내 스낵바
  ├─ [58,500원 결제하기] → 선택된 방법으로 결제 (현금이면 얼럿, 카드면 NFC 화면)
  │
  ├─ 카드 결제 · NFC  (기본 화면, 2.5초 후 "카드번호를 직접 입력할 수도 있어요" 툴팁)
  │    ├─ 일러스트 탭 = 카드 태그 → 결제 진행중 → 결제·배달 완료
  │    └─ [카드 직접 입력] → 카드번호 필드 활성 + 보안키패드 노출
  │                            → 카드번호 16자리 (뒤 8자리 마스킹) → 유효기간 자동 전환
  │                            → 유효기간 4자리 (전부 마스킹) → 키패드 내려가고 [결제하기]
  │                            → 결제 진행중 → 결제·배달 완료
  │
  └─ 현금 결제 확인 얼럿
                            ↓ [현금 결제]
                          결제·배달 완료  (+ "배송수수료 입금" 헤드업 알림, 4.5초 후 사라짐)
                            ├─ [영수증 발송] → 문자 앱으로 이동 (수신 = 고객 안심번호 050-…)
                            │                   → 영수증 이미지 첨부된 메시지 [전송]
                            │                   → 부릉플러스 완료 화면 복귀 + "영수증을 발송했어요"
                            ├─ [현금영수증 발급] → 발급번호 입력 시트 → 번호 입력 후 [확인]
                            │                      ↓
                            │                    발급 완료 → [현금영수증 발급] 버튼 disabled
                            └─ [확인] → 메인 지도 (신규배차 ON)
```

문자 앱에 다녀와 완료 화면으로 돌아올 때는 "배송수수료 입금" 알림이 다시 뜨지 않습니다.

현금영수증 발급번호 입력의 플레이스홀더는 유형에 따라 바뀝니다 —
개인 소득공제용은 `휴대폰번호 또는 사업자등록번호`, 사업자 지출증빙은 `사업자등록번호`.

프레임 하단 캡션의 `처음으로`를 누르면 상태가 초기화됩니다.

## 디자인시스템

[tokens.css](src/styles/tokens.css)의 값은 전부 **부릉플러스 디자인시스템** 라이브러리의 Figma
variable에서 그대로 가져왔습니다. 임의로 정한 컬러·타이포·스페이싱 값은 없습니다.

타이포그래피 클래스는 DS 텍스트 스타일과 1:1입니다 — `.t-h1-32-bold`, `.t-body2-16-medium` 등.

### 폰트

DS의 타이포그래피 variable은 전부 `Noto Sans KR`로 정의되어 있어 그대로 따랐습니다.
**실제 지정 폰트가 다르면** 두 곳만 바꾸면 전체가 따라옵니다:

- [tokens.css](src/styles/tokens.css) → `--vds-font-family`

Google Fonts는 쓰지 않습니다. 단일 HTML로 배포하면 외부 요청이 차단되므로 `@font-face`로
서브셋 woff2를 직접 불러옵니다.

### 아이콘 / 이미지

모든 아이콘은 Figma에서 export한 실제 에셋([src/assets](src/assets))입니다. 직접 그린 SVG는 없습니다.
Figma 에셋 URL은 7일 후 만료되므로 바이트를 저장소에 넣어뒀습니다.

`check.gif`는 완료 화면의 체크 표시입니다 — 원본이
[Lottie 애니메이션](https://lottiefiles.com/animations/check-tD5r7tZ8zu)이라 export 결과가 GIF입니다.
export된 GIF는 **무한 루프**여서 1.8초마다 체크가 사라졌습니다. Netscape 루프 카운트만
`0 → 1`로 무손실 패치해 1회 재생 후 마지막 프레임(체크 완성)에 멈춥니다.

## 디자인과 다르게 구현한 부분

구현 중 판단이 필요했던 지점들입니다. 의도와 다르면 알려주세요.

1. **금액 통일** — 프레임마다 금액이 달랐습니다(배달지 상세 58,500원 / 결제 방법 선택 시트
   60,900원·120,900원). 클릭하며 넘어갈 때 금액이 바뀌면 고장난 것처럼 보이므로 58,500원으로
   통일했습니다. → [order.ts](src/data/order.ts)

2. **현금영수증 시트의 배경** — 디자인(`1723:157212`)에서는 배경이 메인 지도입니다. 하지만
   발급 후 완료 화면(`1723:157237`)으로 돌아와야 하므로, 완료 화면 위에 시트가 쌓이는 구조로
   구현했습니다.

3. **발급번호 입력 시트의 오른쪽 버튼** — 디자인에는 라벨이 "버튼"인 disabled 상태로 놓여
   있습니다. 발급번호를 입력하면 활성화되는 `확인` 버튼으로 해석했습니다.

4. **현금 결제 확인 얼럿에 이르는 두 경로** — `결제 방법 선택 시트에서 현금 선택`과
   `58,500원 결제하기`(현금이 선택된 상태) 둘 다 현금 결제 확인 얼럿을 띄웁니다.

5. **현금 외 결제 방법** — 카드·QR 간편·분할은 선택은 되지만(하단 바와 시트 배지가 바뀝니다)
   후속 화면이 디자인 범위에 없어 안내 스낵바를 띄웁니다. QR 간편·분할 배지 색은 디자인에
   없어 카드와 같은 `Badge_3`를 씁니다.

6. **미션 진행 바** — 디자인은 1/10 항목의 채움 폭이 14px로 고정돼 있지만, 데이터에 비례하도록
   `current/total`로 계산합니다(1/10 → 32px).

7. **고객 전화 / 길 찾기 / VCC 연결 / 문자 전송 / 복사** — 후속 화면이 디자인에 없어
   동작하지 않습니다.

8. **문자 앱 화면 전체** — 디자인이 없어 OS 기본 문자 앱을 추정해 만들었습니다. 전송 버튼을
   누르면 0.7초 후 부릉플러스로 자동 복귀합니다(실제로는 OS가 앱을 전환). 뒤로가기(←)를 누르면
   보내지 않고 돌아옵니다.

9. **NFC 일러스트 애니메이션** — 디자인의 4초 루프(링 2개가 1.1↔0.67 / 1.21↔0.70 배로 펄스,
   카드가 대각선으로 지나감)를 그대로 씁니다. 키프레임 190개를 옮기는 대신 Figma 타임라인을
   MP4로 렌더(`export_video`)한 뒤 일러스트 영역만 잘라 **애니메이션 WebP**(498×400, 96프레임,
   137KB)로 변환했습니다. `<img>`라서 자동 재생·무한 루프됩니다.

10. **카드 태그 방법** — 실제로는 카드를 폰 뒷면에 대면 진행됩니다. 프로토타입에는 누를 것이
    없으면 막히므로 **일러스트를 탭하면 태그로 처리**합니다. 디자인에 없는 조작입니다.

11. **보안키패드를 직접 만들었습니다** — 디자인에는 키패드를 캡처한 이미지가 들어가 있어
    같은 모양으로 동작하는 컴포넌트로 구현했습니다. 숫자는 보안키패드 특성대로 무작위 배치되고
    빈칸이 생기며, 셔플 키로 다시 섞입니다. OS 키보드가 아니라 앱이 그리는 키패드라
    실제 `<input>`을 쓰지 않고 캐럿을 직접 그립니다 — 그래야 폰에서 OS 키보드가 함께
    올라오지 않습니다. 색·치수는 디자인 캡처에서 픽셀을 재서 맞췄습니다
    (배경 `#111111`, 숫자키 `#222222`, 기능키 `#454545`, 키 86×45, radius 8).
    키패드 아래 OS 내비게이션 바도 디자인 캡처에 포함돼 있어 함께 그렸습니다.

12. **유효기간 플레이스홀더** — 디자인에는 빈 상태가 없어 `MM / YY`로 뒀습니다.

13. **발급사 로고 전환 없음** — 디자인의 입력 완료 상태(`1723:157657`)에서는 카드 아이콘이
    우리카드 로고로 바뀝니다. 카드번호로 발급사를 판별하는 건 프로토타입 범위를 넘어서
    기본 카드 아이콘을 유지했습니다.

14. **결제 진행중 스피너** — Figma의 `as_circular_progress`도 애니메이션 노드라 export하면
    첫 프레임(점 하나)만 나옵니다. 원형 진행 표시는 아이콘이 아니라 도형이므로 디자인과 같은
    호를 SVG로 그렸습니다 (지름 40px, 두께 4px, 둥근 끝, 90°, `#0d6dd8`).

15. **완료 화면은 결제 방법에 따라 갈립니다** — 현금은 `현금 결제 금액 (M캐시 차감)`과
    버튼 2개(1723:157236), 카드는 `카드 결제 금액`과 `영수증 발송` 한 개가 전체 폭
    (1723:157270). 카드는 현금영수증 발급이 없습니다.
    단, 카드 완료 화면 디자인에는 "배송수수료 입금" 헤드업 알림이 없는데, 배송 완료 정산은
    결제 방법과 무관한 이벤트라고 보고 카드에서도 띄웁니다.

16. **카드 리더기로 결제 / 카드 스캔하기** — 후속 화면이 없어 안내 스낵바만 띄웁니다.

## 참고

- `npm audit`이 react-router의 RSC 모드 CSRF 권고를 높음으로 표시합니다. 이 프로토타입은 RSC
  모드나 서버 action을 쓰지 않아 해당되지 않습니다. 다운그레이드하면 breaking change가 있어
  그대로 뒀습니다.
- Code Connect 매핑은 붙이지 않았습니다. 실제 앱 코드베이스에 이식할 때 연결하면 이후 codegen
  품질이 올라갑니다.
