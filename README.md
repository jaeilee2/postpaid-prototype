# 후불결제 프로토타입 (부릉 프렌즈 기사앱)

Figma [후불결제](https://www.figma.com/design/u3qTdSzPaWpS6P6AlGdR8w/) 파일의 후불현금 결제 플로우를
클릭 가능한 웹 프로토타입으로 구현한 것입니다. 360×740 (Android 360dp) 기준.

```bash
npm install
npm run dev
```

## 공유 링크 (Wi-Fi 없이 보기)

```bash
npm run build:artifact
```

`dist/artifact.html` 한 장이 나옵니다. 외부 요청이 0이라 어디서든 열립니다 — 폰·다른 사람 기기 모두.
Claude Artifact로 배포된 현재 링크:

**https://claude.ai/code/artifact/b9d6cf80-5c0f-45be-b7af-c128ea577af0** (비공개, 공유는 페이지의 공유 메뉴에서)

화면을 추가한 뒤 갱신할 때는 `npm run build:artifact`를 다시 돌리고 **같은 URL로 재배포**하면 됩니다.

단일 파일로 만들기 위해 한 것들:

| 항목 | 처리 |
| --- | --- |
| 라우팅 | 해시 라우팅(`#/delivery`) — 새로고침·딥링크 동작 → [main.tsx](src/main.tsx) |
| 지도 | 2.3MB PNG → WebP q85 **287KB** (2배 해상도 유지) |
| 폰트 | 외부 CDN 제거, 실제 쓰는 364자만 서브셋해 굵기당 23KB 내장 |
| 에셋 | 전부 data URI로 인라인 → [vite.config.ts](vite.config.ts) |
| 문서 골격 | Artifact가 씌워주므로 벗겨냄 → [scripts/make-artifact.mjs](scripts/make-artifact.mjs) |

최종 크기 **1,256KB** (gzip 약 802KB). 지도(287KB) · 카메라 배경 2장(128KB) ·
NFC 애니메이션(137KB)이 대부분입니다.

### 폰트 서브셋 갱신

새 문자열을 추가하면 그 글자가 폰트에 없어 시스템 폰트로 대체됩니다. 다시 만들려면:

```bash
npm run build && npm run subset:fonts && npm run build
```

먼저 빌드해 번들에 실제 들어간 문자를 뽑고, [scripts/subset-fonts.mjs](scripts/subset-fonts.mjs)가
`pyftsubset`으로 세 굵기를 다시 만든 뒤 한 번 더 빌드합니다.
(`pip install fonttools brotli` 필요, 원본은 맥의
`~/Library/Fonts/NotoSansCJKkr-{Regular,Medium,Bold}.otf`)

## 브라우저 UI 없이 실제 앱처럼 보기

주소창·하단 바를 없애는 방법이 두 가지 있습니다. 둘 중 하나로 들어오면 프레임 아래 캡션까지
사라지고 **화면을 정확히 꽉 채웁니다**(문서 스크롤 0). → [useImmersive.ts](src/hooks/useImmersive.ts)

| 방법 | 되는 곳 | 방법 |
| --- | --- | --- |
| **전체화면** | 안드로이드 크롬 · 데스크톱 | 프레임 아래 캡션의 `전체화면` 누르기 |
| **홈 화면에 추가** | 아이폰 사파리 · 안드로이드 크롬 | 공유 → 홈 화면에 추가 → 홈에서 실행 |

- 아이폰 사파리는 임의 요소의 전체화면 API를 지원하지 않아 `전체화면` 버튼이 나오지 않습니다.
  대신 캡션에 `홈 화면에 추가 → 전체화면`이라고 표시됩니다.
- 전체화면에서 나가려면 **뒤로 제스처**(안드로이드) 또는 **Esc**(데스크톱)입니다.
- `apple-mobile-web-app-capable` / `mobile-web-app-capable` 메타가 있어 홈에서 실행하면
  브라우저 UI 없이 열립니다.

### 좌우 여백 없이 꽉 채우기

폰 화면은 대부분 디자인 기준(360dp)보다 넓습니다 — 아이폰 15/16은 393·402dp. 그래서 폰에서는
**1배를 넘겨서라도 폭에 맞춰 확대**합니다(393dp면 1.09배). Figma 미러링과 같은 방식이라
비율과 위치는 그대로고 전체가 조금 커집니다. 예전에는 1배가 상한이라 좌우에 여백이 남았습니다.

데스크톱은 그대로 디자인 크기(360×740)를 넘지 않습니다.

### 숫자 입력은 OS 키보드를 쓰지 않습니다

현금영수증 발급번호와 분할 결제 금액은 원래 실제 `<input>`이라 OS 키보드가 올라왔는데,
폰에서 **화면이 깨졌습니다.** 이 프로토타입은 360×740 프레임을 `transform: scale`로 띄우는
구조라, 사파리가 "입력 필드를 보이게" 하려고 **페이지 전체를 위로 밀어버립니다** — 그러면
프레임 위쪽이 잘리고 아래에는 배경이 드러납니다. 홈 화면에서 실행하면 특히 심합니다.

`visualViewport`로 키보드 높이를 재서 시트를 그만큼 올려봤지만, **사파리가 높이를 알려주기
전에 이미 밀어버려서** 완전히 막을 수 없었습니다. 그래서 OS 키보드를 아예 쓰지 않습니다 —
카드번호 입력이 보안키패드를 쓰는 것과 같은 방식으로 **앱이 그리는 숫자 키패드**를 넣었습니다.
→ [NumberKeypad.tsx](src/components/NumberKeypad.tsx)

- 필드를 누르면 키패드(264px)가 올라오고 시트가 그만큼 위로 올라갑니다 (`.sheet--lifted`).
  높이를 우리가 정하니 **시트가 잘리지 않습니다** — 분할 결제 시트(476)도 전체가 보입니다.
  264 = 완료 바 44 + 키 4줄 + **아래 여백 20**(맨 아랫줄이 화면 끝에 붙으면 누르기 어려워서).
  두 값이 어긋나면 시트가 키패드에 가리므로 `--numpad-height` 한 곳에서 관리합니다.
- 실제 `<input>`이 아니므로 캐럿을 직접 그립니다 (`.caret`, 카드 키인과 같은 방식).
- 금액은 입력할 때마다 천 단위 콤마가 붙고, 발급번호는 13자리까지 받습니다.
- 이게 디자인과 다른 점입니다 — 실제 앱이라면 이 두 필드는 OS 키보드를 쓸 겁니다.
  프로토타입을 폰에서 안정적으로 보려면 이 방법밖에 없었습니다.

### 홈 화면에서 실행하면 처음으로 돌아가는 방법

홈 화면 실행·전체화면에서는 브라우저 뒤로가기도, 아래 캡션도 없습니다. 그렇다고 프로토타입
버튼을 화면에 띄우면 실제 앱처럼 보이지 않으니, **맨 위 상태바를 탭하면** 아래에서 컨트롤 줄이
올라옵니다 (`처음으로` / `닫기`). 상태바(0~24px)는 장식일 뿐이고 앱바는 24px부터 시작하므로
실제 조작과 겹치지 않습니다. → `ImmersiveControls` in [App.tsx](src/App.tsx)

홈 화면에 추가할 때 **주소창의 URL이 시작 화면이 됩니다.** 항상 배달지 상세에서 시작하게
하려면 해시 없는 주소(`…/postpaid-prototype/`)에서 추가하세요.

그냥 브라우저로 볼 때는 프레임을 **폭 기준으로 맞추고 화면 높이는 기기 높이를 따릅니다** —
하단 바가 화면 밑에 붙고, 여백은 화면 높이에 맞춰 늘거나 줄어듭니다.
디자인 높이(740)에서는 Figma 좌표가 픽셀 단위로 그대로 재현됩니다.

Claude Artifact 링크로 볼 때는 claude.ai의 헤더가 화면 위쪽을 차지하고 iframe이라 전체화면도
막힙니다. 완전히 앱처럼 보려면 **GitHub Pages 링크**를 쓰세요.

## 폰에서 보기 (요약)

`npm run dev`는 `vite --host`로 실행되어 같은 Wi-Fi의 다른 기기에서도 접속할 수 있습니다.
터미널에 찍히는 `Network:` 주소를 폰 브라우저에 입력하세요 (예: `http://10.5.201.154:5173`).
맥의 IP는 `ipconfig getifaddr en0`으로 확인합니다.

폭은 `transform: scale`로 맞추므로 디자인의 픽셀 위치와 비율이 그대로 유지됩니다.
480px 이하에서는 프레임 장식(라운드·그림자)을 없애고 화면 높이를 기기 높이에 맞춥니다.
→ `useDeviceScale` in [App.tsx](src/App.tsx)

`--host`는 0.0.0.0에 바인딩하므로 같은 네트워크의 누구나 접속할 수 있습니다. 사내 Wi-Fi에서 쓸 때는
필요할 때만 켜두세요.

## 카메라 (카드 스캔 / QR)

**실제 카메라를 씁니다.** 권한 팝업에서 허용하면 `getUserMedia`로 뒷면 카메라를 켜고,
스캔 네모 안에 실시간 화면이 보입니다. 카메라를 못 쓰는 환경에서는 디자인에 붙어 있는
카메라 캡처 이미지로 자동 대체됩니다 — 화면 구성은 똑같습니다.

| | 미리보기 | QR 인식 | 카드 OCR |
| --- | --- | --- | --- |
| GitHub Pages (HTTPS) 안드로이드 크롬 | 실제 카메라 | **실제로 읽음** (`BarcodeDetector`) | 시간으로 대체 |
| GitHub Pages iOS 사파리 | 실제 카메라 | 시간으로 대체 | 시간으로 대체 |
| Claude Artifact (iframe) | 캡처 이미지 | 시간으로 대체 | 시간으로 대체 |
| `npm run dev` (localhost) | 맥 카메라 | 브라우저에 따라 | 시간으로 대체 |

- **미리보기**는 HTTPS(또는 localhost)에서만 됩니다. `http://<맥 IP>:5173`으로 폰에서 볼 때는
  안전한 출처가 아니라 캡처 이미지로 대체됩니다. Pages 링크로 열면 실제 카메라가 켜집니다.
- **QR 인식**은 `BarcodeDetector`가 있는 브라우저에서 진짜로 동작합니다 — 아무 QR이나 비추면
  결제가 진행됩니다. 없는 브라우저에서는 3.6초 후 인식된 것으로 처리합니다.
- **카드 OCR**은 브라우저 표준 API가 없습니다. 인식만 시간(2.4초)으로 대체하고, 네모를 눌러
  바로 넘길 수도 있습니다. 인식 결과는 디자인에 적힌 값(`1234 - 1234 - 1234 - 1234` / `12 / 30`)을
  그대로 보여줍니다. → [order.ts](src/data/order.ts)의 `SCANNED_CARD`
- Artifact는 iframe 안에서 열리는데 `allow="camera"`가 없으면 브라우저가 막습니다. 그래서
  아티팩트 링크에서는 캡처 이미지로 보입니다.

카메라 구현은 [useCamera.ts](src/hooks/useCamera.ts) 한 곳에 모여 있습니다.

### NFC — 결제는 못 읽지만, 카드가 닿는 건 감지합니다

웹에서 **카드 결제를 읽는 것은 불가능합니다.** 신용카드·후불교통카드는 ISO 14443/EMV로
통신하는데 브라우저에는 그 명령(APDU)을 보낼 API가 없습니다. 네이티브 앱만 가능합니다.

다만 안드로이드 크롬의 Web NFC(`NDEFReader`)로 **카드가 닿는 순간은 감지할 수 있습니다.**
카드는 NDEF 포맷이 아니라서 `reading`이 아니라 `readingerror` 이벤트가 오는데, 그 이벤트 자체가
"태그가 닿았다"는 신호라 태그 트리거로 씁니다. 그래서 **Pages 링크를 안드로이드 크롬으로 열면
NFC 화면에서 실제로 카드를 대는 것으로 결제가 진행됩니다** (NFC 권한 허용 필요).

iOS·데스크톱·HTTPS가 아닌 곳에서는 아무 일도 하지 않고, 일러스트를 눌러 진행하는 방법이
그대로 남습니다. → [useNfc.ts](src/hooks/useNfc.ts)

Figma 에셋 URL은 7일 후 만료되므로 바이트를 저장소에 넣어뒀습니다.

`check.png`는 완료 화면의 체크 표시입니다 — 원본이
[Lottie 애니메이션](https://lottiefiles.com/animations/check-tD5r7tZ8zu)이라 export 결과가

다시 재생하지 않아서, 완료 화면에 들어와도 체크가 안 보이고 위쪽이 빈 채로 남는 일이 잦았습니다.
그래서 **마지막 프레임(체크 완성)만 PNG로 뽑아** 쓰고 나타나는 느낌은 CSS로 대신합니다
(`check-pop`, 420ms). 120KB → 4.7KB.

`ic-mission.svg`(진행한 미션 불꽃)는 export된 두 벡터(겉 빨간 불꽃 / 안 주황 불꽃)를 **한 장으로
합친 것**입니다. 각각 `<img>`로 얹으면 14px에서 서로 따로 래스터화되어 안쪽 불꽃이 밖으로
삐져나옵니다. Figma의 배치 변환(inset 11.1% / 32.7% / 55.55%)을 계산해 좌표로 넣었습니다.

    캡처 안의 뒤로가기 자리(왼쪽 위 ←, 아래 내비게이션 바 ‹)에 투명 버튼을 얹었습니다.
    캡처라 눌러볼 게 없으니 들어오면 **"테스트를 위해 뒤로가기를 다시 눌러주세요"** 안내를
    4초간 띄웁니다. 캡처 비율이 프레임과 달라 아래가 조금 잘립니다.

40. **카드 취소도 카드 직접 입력·카드 스캔으로 할 수 있습니다** — 태그가 안 되는 경우를 위해
    `/card/cancel/keyin`과 `/card/cancel/scan`을 뒀습니다. 결제 화면과 같은 보안키패드·스캔
    화면을 쓰고 버튼만 `카드 결제 취소`로, 로딩만 `취소 진행중`으로 바뀝니다.
    디자인에는 없는 화면입니다.

42. **현금 취소는 완료 시트 대신 토스트로 알립니다** — 카드 취소에는 완료 시트(`1730:197701`)가
    있지만 현금 취소(`1730:197002`)에는 없습니다. 취소된 게 보이도록
    `현금 결제 취소가 완료되었어요` 토스트를 띄웁니다.

44. **잔여 금액이 있을 때의 `결제하기`** — 두 갈래입니다.
    - **분할 결제 중**이면 분할 결제 시트를 바로 엽니다 (`1730:196227` — 상품가액을 다 받았으면
      금액 필드가 비활성되고 컵 보증금만 남은 상태로 뜹니다). 배달지 상세의 CTA와
      수행목록의 `결제하기` 둘 다 같습니다.
    - 애초에 **한 회차를 받고 남으면 시트가 저절로 다시 열립니다** — 이어서 다음 회차를 받는
      흐름이라 버튼을 다시 누를 필요가 없습니다. 카드·QR 회차는 그 화면을 다녀와
      배달지 상세로 돌아오면서 열립니다.
    - 그 밖에(취소해서 남은 경우 등)는 결제 방법 시트를 다시 띄웁니다
      (`1730:196113` → `1730:196101`) — 지난 방법으로 바로 넘어가지 않습니다.

    고른 방법에는 **남은 금액만** 실어 보냅니다 — 전액을 다시 받으면 과결제가 되기 때문입니다.

45. **전화 앱은 아무 곳이나 누르면 넘어갑니다** — 캡처(`1773:130318`)라 눌러볼 게 없어서
    화면 전체를 히트 영역으로 뒀습니다. 안내도 `아무 곳이나 누르면 취소가 접수돼요`입니다.
    KIS Pay는 왼쪽 위 ←와 아래 내비게이션 바 ‹ 두 곳만 눌립니다.

46. **결제 건이 둘 이상이면 완료 화면에 건별 내역이 붙습니다** — 분할뿐 아니라 취소 후
    다른 방법으로 다시 받은 경우도 총액 + 건별 내역으로 보여줍니다.
    건별 금액은 총액과 **같은 크기**입니다(`1730:197859`) — 처음에 한 단계 작게 넣었다가
    정정받았습니다. 라벨의 M캐시 표기도 디자인대로 `(M캐시 차감)` 괄호입니다.

48. **분할 결제 시트의 비활성 버튼** — 회색 배경(`#dde0e3`)에 **흰색 40%** 글자이고
    (`1730:197778`, 기본 버튼 비활성과 같은 조합) 아이콘도 **회색 전용 에셋**입니다
    (`#EBEDEF` · `#C7CCD1`). 글리프는 활성과 같고 색만 달라서 `IcQr`/`IcCash`/`IcCard`의
    `off` prop으로 에셋을 갈아끼웁니다. 처음에는 진회색 글자에 아이콘을 `opacity`로 흐리게 해서
    디자인보다 어둡고 흐릿했습니다 — CSS 필터·투명도로는 디자인 색이 안 나옵니다.

50. **결제하지 않고 나오면 결제 방법을 다시 묻습니다** — 카드 결제 화면 뒤로가기, QR 간편 결제
    닫기(X), 분할 결제 시트 닫기(X) 모두 `어떻게 결제하시겠어요?` 시트로 이어집니다.
    결제를 중간에 그만둔 것이지 결제를 안 하려는 건 아니라고 보고 방법을 다시 고르게 합니다.

49. **현금 결제 확인 얼럿의 왼쪽 버튼은 `다른 결제방법`입니다** — 디자인(`1723:156090`)은
    `취소`인데, 여기서 다른 방법으로 바로 갈 수 있어야 해서 바꾸고 닫기는 오른쪽 위 X로
    옮겼습니다 (2026-07-29 이재이 확인). 분할 결제 회차에서 띄운 경우에는 둘 다 분할 결제
    시트로 돌아가고 **입력했던 금액이 유지됩니다.**

47. **수행목록 뒤로가기는 지도 화면으로 갑니다** — history를 되짚으면(`navigate(-1)`)
    결제 내역을 거쳐 온 경우 결제 내역으로 돌아가버립니다. 그래서 상태로 판단합니다 —
    결제를 다 받았으면 메인 지도(완료 → 확인으로 들어온 경로), 그 전이면 배달지 상세입니다.

43. **수행목록의 잔여 결제 금액 안내** — 잔여가 있으면 노란 박스(`#fff4db`)에
    `⚠ 잔여 결제 금액: 28,200원`과 [결제내역] [결제하기]가 들어갑니다 (`1730:196061`).
    결제 상단 줄도 `결제필요금액 58,500원`으로 바뀝니다(다 받으면 `58,500원 결제완료`).
    `결제하기`는 배달지 상세와 **같은 결제 흐름**을 씁니다 — `usePaymentFlow`로 묶었습니다.

41. **서명은 결제할 때마다 받습니다** — 처음에는 한 번 받은 서명을 재사용해서, 두 번째 카드
    결제에 서명 화면이 뜨지 않는 문제가 있었습니다. 5만원 이상이면 매번 받습니다.

## 참고

- `npm audit`이 react-router의 RSC 모드 CSRF 권고를 높음으로 표시합니다. 이 프로토타입은 RSC
  모드나 서버 action을 쓰지 않아 해당되지 않습니다. 다운그레이드하면 breaking change가 있어
  그대로 뒀습니다.
- Code Connect 매핑은 붙이지 않았습니다. 실제 앱 코드베이스에 이식할 때 연결하면 이후 codegen
  품질이 올라갑니다.
